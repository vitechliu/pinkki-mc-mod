# Minecraft 模型设计与审阅

## 开始前

- 读取仓库根目录 `AGENTS.md`，检查工作区和相关设计现状；保留用户已有修改。默认目标是 1.20.1 Forge，当前依赖以构建配置及 [GeckoLib 兼容说明](../../../docs/geckolib-compatibility.md) 为准，不把本 skill 中的历史样例当成当前依赖配置。
- 从参考、用户已确认的取舍和现有资产继续工作。信息足够就制作可审阅初稿；只对影响主体方向的缺失信息提问，并继续不依赖回答的工作。
- 默认完成设计与审阅。用户同时要求游戏实现时继续完成获授权的接入工作，不把每一步都变成确认关卡。用户只要求设计时，不擅自注册实体、改游戏行为、部署或发布。
- 本流程的浏览器/Blockbench 审阅不是 Minecraft 实机测试；仍遵守默认禁止启动游戏客户端的项目规则。

## 1. 将参考转成模型与动作规格

用简短说明记录主体轮廓、体型尺度、配色、识别特征和可调整部分。默认延续本项目已确认的 Minecraft 长方体与像素贴图风格，用户另有风格要求时按其要求评估格式能力。

按用途选格式，不因形状不规则就强制使用 GeckoLib：

| 用途 | 初始选择 | 需要明确的事项 |
| --- | --- | --- |
| 生物、NPC、Boss | Blockbench GeckoLib 工程及几何/动画资源 | 骨骼、装备或乘客关系、动作与游戏状态 |
| 静态工作方块、物品 | Java Block/Item 模型与贴图 | 方块朝向、显示变换、碰撞/交互轮廓 |
| 有骨骼动画的机器/方块 | 按实际渲染方案选择 GeckoLib | 方块实体渲染、动画触发与服务端状态 |

- 用户要求参考原版行为时，核对目标版本本地源码/映射或官方资料；区分原版事实与本次设计值，不声称未经核对的逐帧复刻。
- 动作规格写清名称、循环/单次、时长、姿态阶段及未来触发条件。生物按实际需要考虑待机、行走、跳跃、游泳、鸣叫/捕食；NPC/Boss 按需求考虑持物、前摇、攻击、后摇、受击等，不凑固定动作数量。
- 将装饰骨骼、装备挂点、独立乘客分清。攻击的视觉接触时刻可标记，但动画不负责伤害判定；根运动、服务端位移、AI、碰撞和网络同步单独设计。

## 2. 制作可编辑、可复现的设计资产

资产放在 `designs/<英文标识>/`，沿用现有目录时先确认源文件与生成方式。设计稿不自动进入运行资源。参考 [饼蛙样例](../../../designs/bingwa/README.md)，按需交付：

- 可编辑 `.bbmodel`，包含骨骼、UV、贴图及已设计动画；避免依赖本机绝对纹理路径。
- GeckoLib 的 `.geo.json`、`.animation.json` 与 PNG，或相应的静态方块/物品 JSON。
- 可旋转的 `review.html`、必要的生成/校验脚本及简短设计说明。

制作时明确模型单位、地面原点、正面方向、关节 pivot 与父子关系。贴图按实际 UV 绘制像素细节；不要用参考插画的平面投影冒充完整三维贴图。尺寸、UV 和骨骼命名保持一致，贴图分辨率按细节需要选择。

优先沿用现有可复现资产工具；新写生成器必须输出确定性数据。避免为一个模型创建尚无需求的通用建模框架。饼蛙的部件数量、配件、坐标和动作是样例，不能变成其他模型的硬编码约束。

格式、坐标和编辑器导入的易错点见 [资产与审阅技术说明](references/asset-review.md)。

## 3. 提供真实 3D 审阅

- 交付基于实际导出几何、纹理、骨骼和关键帧的审阅器；优先共享同一源数据或校验两者一致，不能仅提供效果图或另一套近似模型。
- 支持拖动旋转、缩放、正面/侧面/背面/三分之四视角；有动画时支持选择、播放/暂停和时间轴拖动。按需要增加骨骼或配件开关，父子可见性保持一致。
- 可在可用时使用 `visualize` skill 展示内联审阅，先读取该 skill；没有该能力时仍交付本地可打开的审阅文件与 Blockbench 工程。独立审阅器尽量内嵌资产，避免远程 CDN 和联网取纹理。
- 审阅器辅助添加的腾空轨迹、水面高度等明确标为预览效果；不能误写进未来由实体物理驱动的位移。
- 在实际浏览器和 Blockbench 中打开并检查：各方向轮廓、贴图/UV、关节与父子关系、动画列表、起止帧、最大伸展、穿插、滑步、循环衔接，以及审阅控件是否生效。保存必要截图/日志到 `.local/<标识>-review/`。
- 静态方块重点审阅各面纹理、朝向和物品显示姿态，不附加无用途的动画控件。预览视觉包围盒不代表游戏碰撞箱。

## 4. 校验资产与兼容边界

- 运行与资产匹配的无头检查：JSON/PNG 可读、有限数值、合法尺寸、UV 范围、骨骼命名与引用、父子无环、关键帧时间和向量、贴图引用，以及源工程/导出/审阅数据一致性。
- 使用项目实际最低 GeckoLib 依赖解析几何和动画；若要宣称支持整合包中的其他版本，再用对应目标/加载器的实际库校验。优先采用基础数值关键帧与已验证格式，使用新特性时明确提升依赖的影响。
- 解析通过只证明资产可解析；Blockbench 打开和浏览器显示也不证明 Minecraft 渲染、物理、攻击命中或整合包兼容。不沿用饼蛙或其他模型的通过结论。
- 仅设计/skill/文档改动不启动 Minecraft、不例行重建 mod。若已获授权接入游戏，则按项目规则运行 1.20.1 构建、发行包校验和适用的无头验证，分别报告证据。
- 资源可复用与加载器/API 可兼容是两件事。不把一个目标 JAR 声明兼容其他版本；只有用户明确要求其他目标才使用 `$port-minecraft-version`。

## 5. 交付与迭代

交付工程和 3D 审阅入口，概括造型/动作取舍、实际验证、未验证范围及少量值得用户审阅的要点。用户反馈后修改源资产并重新生成、校验和审阅，避免只改预览。

更新设计目录说明，记录生成命令、动作规格及设计稿/已接入状态。新增游戏资源契约或行为时按 `docs/porting/change-template.md` 写 `docs/changes/`；纯 skill/文档修改不制造游戏功能待办。没有完成对应版本适配与验证时不推进检查点。
