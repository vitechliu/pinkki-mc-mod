# 饼蛙：第一版造型与动作审阅

造型和动作已获确认，并接入 1.20.1 Forge / GeckoLib。此目录保留可编辑源工程与审阅器，运行资源位于该目标的 `assets/pinkkicore/`。实体 ID 为 `pinkkicore:bingwa`，刷怪蛋为 `pinkkicore:bingwa_spawn_egg`；主世界草地稀有自然生成，中立受击反击。详见 [玩家条目](../../wiki/bosses.md#bingwa)。

## 参考与造型取舍

参考图由用户提供，保留扁宽浅奶油色身体、浅黄绿色大眼睛、短粗外张四肢、三趾脚掌、头顶小蛙和橘子。将插画曲面转译为 Minecraft 风格的分层长方体，不复制原版模型或贴图。橘子、小蛙是本体骨骼上的装饰部件，本稿不将它们解释为第二只生物或乘客。

本稿包含 75 个长方体、20 根骨骼、256×256 像素贴图。16 个模型单位相当于一格；姿态原点在足部地面。主体宽约 1.65 格（含外张后脚），静态总高约 1.32 格（含橘子）。游戏碰撞箱、寻路宽度应在接入时单独确定，不能按橘子外框自动生成。

## 行动方向

按照原版青蛙的陆地行走、跳跃、水中移动/待机、鸣叫和吐舌捕食来划分动作，保留两栖、小步挪动与间歇跳跃的方向，游戏中采用中立受击反击规则。动画时长为本稿设计值，不声称逐帧复刻原版。

| 动作 | 时长 | 本稿设计 |
| --- | --- | --- |
| 陆地待机 `idle` | 2.4 秒循环 | 小幅呼吸、喉部起伏、小蛙轻微摆动 |
| 陆地行走 `walk` | 1.2 秒循环 | 左右前肢交替、后肢配合，身体轻微摇摆 |
| 跳跃 `jump` | 1.2 秒单次 | 蓄力、后腿展开、腾空姿态、落地恢复 |
| 游泳 `swim` | 1.1 秒循环 | 后腿蹬水，前肢划动 |
| 水中待机 `float` | 2.6 秒循环 | 四肢略张，身体小幅浮动 |
| 鸣叫 `croak` | 1.4 秒单次 | 鼓喉，轻微抬头 |
| 吐舌 `tongue` | 0.8 秒单次 | 张下颌、伸舌、回收、合拢 |

跳跃的升降轨迹和水中悬浮高度仅由审阅器附加，用于看清动作，不在导出的骨骼动画中驱动实体世界位移。游戏中由服务端实体物理、AI 状态和网络同步控制实际移动；吐舌动画不直接判定命中。游戏实现采用两栖寻路、陆地间歇跳跃和水中移动，并以吐舌作中立反击；不是逐项移植原版 Frog 的 Brain。捕食、繁殖与蝌蚪、自然生成、专属掉落和食物规则尚未接入。

原版依据：[Java 1.19 官方更新说明](https://www.minecraft.net/en-us/article/the-wild-update-out-today-java)。还核对了本地 1.20.1 映射 JAR 的 `FrogAnimation`、`Frog`：存在 walk / jump / swim / idle-water / croak / tongue 动画或状态；本稿为重新设计的独立资产。

## 审阅与修改

聊天中的交互模型可拖动旋转、滚轮缩放、切换正面/侧面/背面、逐帧拖动动作时间、播放/暂停，也可隐藏小蛙、橘子和显示骨骼。橘子属于小蛙的子部件，隐藏小蛙时一起隐藏。

建议首先审阅：

1. 主体是否足够扁、胖、像“饼”；Minecraft 方块化程度是否合适。
2. 眼距、瞳孔、嘴部开合与三趾脚掌的比例。
3. 是否保留头顶小蛙和橘子，以及它们的大小、位置。
4. 行走是否够憨、跳跃是否够轻快；吐舌和鸣叫的节奏。

使用 [Blockbench 网页版](https://web.blockbench.net/) 或桌面版，安装官方插件商店的 **GeckoLib Models & Animations**，通过“打开模型”选择 `bingwa.bbmodel`。其贴图和七段动画已嵌入源文件，无需联网下载纹理。切换 Animate 模式查看动作。`.bbmodel` 使用 4.10 工程格式，已经在当前网页版与 GeckoLib 插件中实际打开过；新 Blockbench 的工程格式与游戏运行资产的版本是两件事。

## 文件与生成

- `bingwa.bbmodel`：可编辑源工程，包含纹理、骨骼和动画。
- `bingwa.geo.json`：GeckoLib 几何数据，格式 1.12.0。
- `bingwa.animation.json`：基础数值关键帧，格式 1.8.0；不使用 Bezier、复杂 Molang 或新版特性。
- `textures/bingwa.png`：原生像素贴图，未使用插画投影贴图。
- `review.html`：独立数据的交互审阅片段，读取与导出文件相同的几何、纹理和关键帧；不依赖远程 CDN。
- `generate.py`、`review-template.html`：可重复生成资产和审阅片段。
- `validate.py`：检查 UV、骨骼引用、动画、PNG、源工程导出坐标与审阅资产的一致性。
- `GeckoAssetCheck.java`：使用实际 GeckoLib 解析器进行无头资产解析，不启动 Minecraft。

在仓库根目录执行：

```bash
python3 designs/bingwa/generate.py
python3 designs/bingwa/validate.py
```

此目录的源工程和审阅页面不直接入包。确认后的几何、动画和贴图复制到 1.20.1 运行资源；变更后需检查源资产与入包文件一致，重新构建及无头验证。
